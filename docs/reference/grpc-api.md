# gRPC API Reference

!!! note
    For the embedded dashboard JSON API, see [Dashboard HTTP API](dashboard-api.md).

HitStor uses gRPC over TLS for communication between components. There are two gRPC services:

- **BackupService** — server-side, handles agent-to-server backup operations (`internal/proto/hitstor/v1/backup.proto`)
- **AgentService** — agent-side, handles server-to-agent management operations (`internal/proto/hitstor/v1/agent.proto`)

## Service: `BackupService`

| RPC | Type | Description |
|-----|------|-------------|
| `BeginSession` | Unary | Start a backup session, receive chunker parameters and IDKey |
| `CheckBlobs` | Unary | Check which blob IDs the server already has (batch) |
| `UploadChunks` | Client streaming | Stream compressed chunks to the server |
| `FinalizeBackup` | Unary | Send file tree, create snapshot, end session |
| `Ping` | Unary | Health check, returns server version |
| `GetSchedule` | Unary | Query backup schedule for this agent |

## Authentication

All BackupService RPCs (except `Ping`) require a valid API key. The key is a 64-character hex string, either generated by `hitstor serve agent add <name>` (CLI) or sent to the agent during dashboard registration.

- `BeginSession` and `GetSchedule`: API key is sent in the request message (`api_key` field)
- `CheckBlobs`, `UploadChunks`, `FinalizeBackup`: Authenticated by `session_id` from `BeginSession`
- `Ping`: No authentication required

## Backup Flow

```
Agent                                          Server
  |                                              |
  |-- BeginSession(api_key, hostname, paths) --> |
  |<-- session_id, id_key, chunker params -------|
  |                                              |
  |  [scan files, chunk with FastCDC,            |
  |   compute blob IDs with id_key]              |
  |                                              |
  |-- CheckBlobs(session_id, blob_ids[]) ------> |
  |<-- needed_ids[] -----------------------------|
  |  (repeat in batches of ~1000)                |
  |                                              |
  |-- UploadChunks(stream) --------------------> |
  |   [blob_id + compressed_data per chunk]      |
  |<-- chunks_received, bytes_received ----------|
  |                                              |
  |-- FinalizeBackup(session_id, files[]) ------> |
  |<-- snapshot_id, stats -----------------------|
```

## RPCs

### BeginSession

Starts a backup session for an authenticated agent.

**Request: `BeginSessionRequest`**

| Field | Type | Description |
|-------|------|-------------|
| `api_key` | string | 64-character hex API key |
| `hostname` | string | Hostname of the machine being backed up |
| `paths` | repeated string | Absolute paths being backed up |
| `excludes` | repeated string | Glob patterns to exclude |
| `tags` | repeated string | Optional snapshot tags |
| `job_id` | string | Backup job ID (links session to a dashboard job) |

**Response: `BeginSessionResponse`**

| Field | Type | Description |
|-------|------|-------------|
| `session_id` | string | Unique session identifier |
| `id_key` | bytes | 32-byte HMAC-SHA256 key for computing blob IDs |
| `chunker_min` | uint32 | Minimum chunk size in bytes (default: 262144) |
| `chunker_avg` | uint32 | Average chunk size in bytes (default: 1048576) |
| `chunker_max` | uint32 | Maximum chunk size in bytes (default: 4194304) |
| `previous_files` | repeated `PreviousFileEntry` | Metadata from parent snapshot for incremental detection |
| `parent_snapshot_id` | string | Hex ID of parent snapshot (empty for full backup) |

**`PreviousFileEntry` fields:** `path`, `mtime_ns`, `size`, `content_ids` (ordered chunk blob IDs).

### CheckBlobs

Checks which blob IDs the server already has. Called in batches (recommended: 1000 IDs per call).

**Request: `CheckBlobsRequest`**

| Field | Type | Description |
|-------|------|-------------|
| `session_id` | string | Session from `BeginSession` |
| `blob_ids` | repeated bytes | Batch of 32-byte blob IDs to check |

**Response: `CheckBlobsResponse`**

| Field | Type | Description |
|-------|------|-------------|
| `needed_ids` | repeated bytes | Blob IDs the server does NOT have (upload these) |

### UploadChunks

Streams compressed chunks to the server. Client-side streaming RPC -- the agent sends multiple `UploadChunkMessage` messages on a single stream.

**Request (stream): `UploadChunkMessage`**

| Field | Type | Description |
|-------|------|-------------|
| `session_id` | string | Session from `BeginSession` |
| `blob_id` | bytes | 32-byte blob ID (HMAC-SHA256 of uncompressed data) |
| `compressed_data` | bytes | Zstd-compressed chunk data |
| `uncompressed_length` | uint32 | Original uncompressed size in bytes |

**Response: `UploadChunksResponse`**

| Field | Type | Description |
|-------|------|-------------|
| `chunks_received` | uint32 | Total chunks received and stored |
| `bytes_received` | uint64 | Total compressed bytes received |

### FinalizeBackup

Sends the complete file/directory tree and closes the session. The server builds tree blobs, creates a snapshot, and returns summary statistics.

**Request: `FinalizeBackupRequest`**

| Field | Type | Description |
|-------|------|-------------|
| `session_id` | string | Session from `BeginSession` |
| `files` | repeated `FileNode` | Complete directory tree |
| `backup_type` | string | `"full"` or `"incremental"` |
| `parent_snapshot_id` | string | Parent snapshot hex ID (incremental only) |

**`FileNode` fields:**

| Field | Type | Description |
|-------|------|-------------|
| `path` | string | Relative path (forward slashes, no leading slash) |
| `is_dir` | bool | `true` for directories |
| `mode` | uint32 | Unix file mode (permissions) |
| `mtime_ns` | int64 | Modification time (nanoseconds since Unix epoch) |
| `size` | int64 | File size in bytes (0 for directories) |
| `uid` | uint32 | Owner user ID |
| `gid` | uint32 | Owner group ID |
| `content_ids` | repeated bytes | Ordered chunk blob IDs (files only) |
| `link_target` | string | Symlink target path (symlinks only) |

**Response: `FinalizeBackupResponse`**

| Field | Type | Description |
|-------|------|-------------|
| `snapshot_id` | string | 8-character hex prefix of the snapshot ID |
| `files_new` | uint64 | Number of new files |
| `files_unchanged` | uint64 | Number of unchanged files |
| `bytes_added` | uint64 | New data added to repository |
| `bytes_processed` | uint64 | Total data processed |
| `duration_seconds` | double | Backup duration |

### Ping

Health check RPC. No authentication required.

**Request:** `PingRequest` (empty)

**Response: `PingResponse`**

| Field | Type | Description |
|-------|------|-------------|
| `version` | string | HitStor server version |
| `repo_id` | string | 64-character hex repository ID |

### GetSchedule

Returns the backup schedule configured for this agent.

**Request: `GetScheduleRequest`**

| Field | Type | Description |
|-------|------|-------------|
| `api_key` | string | 64-character hex API key |

**Response: `GetScheduleResponse`**

| Field | Type | Description |
|-------|------|-------------|
| `enabled` | bool | Legacy: first enabled job (backward compatibility) |
| `interval_hours` | int32 | Legacy: interval from first job |
| `next_run_unix` | int64 | Legacy: next run from first job |
| `jobs` | repeated `ScheduledJob` | All backup jobs for this agent |

**`ScheduledJob` fields:** `job_id`, `name`, `paths`, `excludes`, `repo_name`, `enabled`, `interval_hours`, `next_run_unix`, `run_now`, `full_rescan_days`, `last_full_backup_unix`, `cron_expression`, `timezone`, `use_vss`.

## Transport

- **Protocol:** gRPC over TLS (required)
- **Port:** 8420 (default, configurable via `serve_port`)
- **TLS:** Server generates self-signed certificate if none provided; agents can use `--ca-cert` to trust custom CAs
- **Max message size:** ~2 GiB (set by go-plugin framework; pack files cap at 128 MiB)

## Error Codes

| gRPC Code | Meaning |
|-----------|---------|
| `Unauthenticated` | Invalid or missing API key |
| `NotFound` | Unknown session ID |
| `FailedPrecondition` | Pre-backup hook rejected the operation |
| `Internal` | Server-side error (check logs) |

## Service: `AgentService`

The AgentService runs on each agent (default port 8422) and handles server-to-agent management operations. The server connects to this service when adding agents from the dashboard, browsing filesystems, or configuring backup paths.

| RPC | Type | Description |
|-----|------|-------------|
| `Register` | Unary | Register the agent with a server (send API key + server address) |
| `ListDirectory` | Unary | List files and directories at a path on the agent |
| `Configure` | Unary | Set backup paths and exclude patterns on the agent |
| `AgentInfo` | Unary | Query agent hostname, version, OS, paths, and registration status |
| `RestoreData` | Client streaming | Stream restore data to agent |
| `WakeUp` | Unary | Signal agent to check schedule immediately (dashboard "Backup Now") |

### AgentService Authentication

All AgentService RPCs require a valid **agent token** — a 64-character hex string generated during agent installation. The token is sent in the `token` field of each request message.

### Register

Called by the server when an admin adds the agent from the dashboard. The server sends an API key and its address; the agent stores them and starts the backup loop.

**Request: `RegisterRequest`**

| Field | Type | Description |
|-------|------|-------------|
| `token` | string | 64-character hex agent token |
| `api_key` | string | API key for agent-to-server backup authentication |
| `server_addr` | string | Server address (`host:port`) for backup push |
| `server_ca_cert` | bytes | PEM-encoded TLS certificate (optional) |

**Response: `RegisterResponse`**

| Field | Type | Description |
|-------|------|-------------|
| `hostname` | string | Agent machine hostname |
| `version` | string | Agent binary version |
| `os` | string | Operating system (for example, `linux`) |
| `arch` | string | Architecture (for example, `amd64`) |

### ListDirectory

Browse the agent's filesystem. Called when the admin expands a directory in the dashboard's filesystem tree browser.

**Request: `ListDirectoryRequest`**

| Field | Type | Description |
|-------|------|-------------|
| `token` | string | 64-character hex agent token |
| `path` | string | Absolute path to list (empty string returns root-level directories) |

**Response: `ListDirectoryResponse`**

| Field | Type | Description |
|-------|------|-------------|
| `entries` | repeated `DirEntry` | Directory entries, sorted directories-first |

**`DirEntry` fields:**

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Entry name |
| `path` | string | Absolute path |
| `is_dir` | bool | `true` for directories |
| `size` | int64 | File size in bytes (0 for directories) |
| `mode` | uint32 | Unix file mode |
| `readable` | bool | Whether the agent process can read this path |
| `has_children` | bool | Whether this directory contains subdirectories (hint for UI expand icon) |

### Configure

Set backup paths and exclude patterns on the agent. Called when the admin clicks "Save Backup Paths" in the dashboard.

**Request: `ConfigureRequest`**

| Field | Type | Description |
|-------|------|-------------|
| `token` | string | 64-character hex agent token |
| `backup_paths` | repeated string | Absolute paths to back up |
| `excludes` | repeated string | Glob patterns to exclude |

**Response: `ConfigureResponse`**

| Field | Type | Description |
|-------|------|-------------|
| `success` | bool | Whether the configuration was saved |
| `message` | string | Status message |

### AgentInfo

Query the agent's current state.

**Request: `AgentInfoRequest`**

| Field | Type | Description |
|-------|------|-------------|
| `token` | string | 64-character hex agent token |

**Response: `AgentInfoResponse`**

| Field | Type | Description |
|-------|------|-------------|
| `hostname` | string | Agent machine hostname |
| `version` | string | Agent binary version |
| `os` | string | Operating system |
| `arch` | string | Architecture |
| `backup_paths` | repeated string | Currently configured backup paths |
| `excludes` | repeated string | Currently configured exclude patterns |
| `registered` | bool | Whether the agent is registered with a server |
| `server_addr` | string | Registered server address (empty if not registered) |

### WakeUp

Called when an admin triggers "Backup Now" from the dashboard so the agent does not wait for the next poll interval.

**Request:** `WakeUpRequest` — `token` (64-char hex agent token)

**Response:** `WakeUpResponse` — `acknowledged` (bool)

## AgentService Transport

- **Protocol:** gRPC over TLS (self-signed, auto-generated by the agent)
- **Port:** 8422 (default, configurable via `--listen-port` or `HITSTOR_AGENT_LISTEN_PORT`)
- **TLS:** Agent generates a self-signed certificate; the server uses `InsecureSkipVerify` since the token provides authentication
